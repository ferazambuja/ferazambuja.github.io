Predicting color on a six-state e-paper display

Fernando Voltolini · Independent engineering project · Investigation in progress

I have long been fascinated by the way e-paper creates images with reflective pigments instead of glowing pixels. Spectra 6 was my first color e-paper display, and I wanted to understand how it made color and whether I could improve the result.

I began with an experimental ICC profile, a color-management description of a fixed rendering-and-display setup, applied before Pimoroni's image conversion. While evaluating the display, I found that rearranging the same native colors could change the measured output. That surprise led to controlled pattern tests and limited color predictions. An experimental renderer now uses measured native colors; predicting the output of their combinations reliably remains an open question.

What the experiments showed

  • A useful first improvement: an experimental profile reduced average color error in a measured 133-color grid, using the same image renderer.
  • Pixel organization mattered: equal native-color counts did not guarantee equal measured output, across more than blue/green stripes.
  • Prediction and reproduction diverged: some exact outputs were predicted successfully; broad accuracy and matching desired image colors remain open.

Why the pixel pattern matters

Rendering intermediate colors with six pixel states

Most conventional RGB display systems create a requested color by varying the red, green, and blue channel output within each pixel. At the controller interface used in this project, a Spectra 6 pixel is instead assigned one of six native color states: black, white, red, yellow, green, or blue.

To create colors between those native states, a renderer distributes them across neighboring pixels. This is spatial color mixing, often called halftoning or dithering. From a normal viewing distance, the small pattern can blend into an intermediate color. There is no native cyan or magenta state at this controller interface; those and other intermediate colors depend on spatial mixing.

The renderer still has to choose an exact pixel arrangement. That makes the pattern part of the color-generation problem, not merely a decorative detail.

Why prediction matters: if spatial construction helps create the color, the renderer must either predict the output of the construction it sends to the display or restrict itself to exact constructions whose output has been measured and validated for that setup and chosen tolerance. A future ICC-style characterization can describe only a fixed, tested rendering process. Prediction results later on this page show both where this worked and where it did not transfer.

For the physical display technology, see E Ink's explanation of how electronic ink works, including the four-particle system used by Spectra 6. The pigment system inside the screen and the six color states available to this project's image renderer are different layers.

The display and the software behind it

The hardware I used is the Pimoroni Inky Impression 7.3-inch, a color e-paper display for DIY electronics projects that connects to a Raspberry Pi. It combines E Ink Spectra 6 panel technology with Pimoroni's board and Python software and image examples.

Pimoroni's image-conversion software is the starting renderer here. It takes an ordinary RGB image, chooses among the six native states, and distributes those choices across neighboring pixels using dithering. I could therefore begin with a working image display and ask whether measured color information could improve its choices.

E-paper displays for DIY projects

Modules like this let people build their own picture frames, signs, and other devices without designing the display electronics from scratch. Other suppliers, including Waveshare and Good Display, also provide color e-paper hardware with example code. Their software and image-preparation routes differ; the Pimoroni route tested here is one specific implementation, not a result for every Spectra 6 product.

What the two experimental profile versions describe

“Sparse” and “dense” refer to the color grids used to construct the profiles, not the display's pixel density. The dense version used a modeled grid built from measured native states and an optical mixture model. The artwork route used relative-colorimetric conversion before the unchanged palette separation. This early Argyll-based experiment is distinct from the device-neutral ICC profile-writing tool now being developed.

Adding the ICC conversion changed the pixels Pimoroni chose and reduced average error on the measured grid. That was encouraging without replacing the renderer. To improve the choice of pixels further, I needed to check a basic assumption: did the color model describe what those patterns actually produced?

The measurement that changed the question

Equal color counts produced different measured colors

While measuring patterns to understand the display's color response, I came across something I had not expected: two blue/green patterns with the same color counts gave different readings. One used horizontal rows; the other used vertical columns. I had started by trying to improve image color. Now I also needed to understand why the exact arrangement could matter.

A simple area-count description would treat these two patterns alike. These enlarged repeating illustrations show the difference it missed. In each full 800×480 source image, the exact payload contains 192,000 blue and 192,000 green pixels. Only their spatial organization differs. The illustrations are not photographs or simulations of how the colors looked.

A larger difference: the black/yellow patterns

Blue/green prompted the investigation. Later, a one-pixel black/yellow comparison showed a much larger lightness difference. The two curves show how much light each horizontal and vertical pattern reflected at each wavelength. The lower curve shows their wavelength-by-wavelength difference. Reading this example: the spectrum records reflected light across wavelengths. From it, XYZ describes color under a specified illuminant and observer; Lab expresses that color as lightness (L*), green–red (a*) and blue–yellow (b*) coordinates. DeltaE00 summarizes how far apart the two colors are. RMS instead summarizes the size of their spectral difference.

Here, H means horizontal and V means vertical. H minus V keeps the direction: a positive L* difference means H measured lighter, positive a* means redder, and positive b* means yellower. Repeated readings show how much each pattern changed over time.

How to read the spectra, color distances, and repeated readings

Different measurements answer different questions

The black/yellow example combines two questions: how did the reflected spectrum change, and how did the resulting color change? The blue/green and red/green examples below show why their answers need not track one another. Spectral RMS is useful because it summarizes the average size of a difference across the measured wavelengths. It does not say what either color was, which way the color moved, how far apart the colors are perceptually, or whether a model predicted either one.

RMS means root mean square. At each wavelength, the vertical mean spectrum is subtracted from the horizontal mean spectrum. RMS squares those signed differences so positive and negative regions cannot cancel, averages the squared values, and takes the square root. The result is therefore an unsigned size in percentage points. A value such as 1.58 pp RMS is not automatically large or small; it needs the absolute colors, signed spectral shape, DeltaE00 color distance, and repeated-reading movement beside it.

Each curve is the mean of two readings from one four-reading comparison. The same native plotting style is used later in the interactive atlas, where all four individual spectra can also be inspected.

Measured color: XYZ and Lab

Where the horizontal and vertical patterns landed in standard color coordinates. These are the values a future color model must predict. CIE colorimetry recommendations define the underlying conventions.

Direction of the change

Which way lightness, chromatic components and each wavelength moved. Direction disappears in an unsigned magnitude.

Perceptual distance: DeltaE00

How far apart the two measured colors are under the stated white-reference convention. It is a distance, not automatically a visibility threshold. See Luo, Cui and Rigg (2001) for the development of CIEDE2000.

Spectrum difference: RMS

The unsigned root-mean-square size of the wavelength-by-wavelength difference. Useful, but not the color itself and not a direction.

Why the distinction matters: in the all-pair study, a one-pixel red/green pattern had lower spectral RMS than blue/green (1.58 versus 1.97 percentage points) but a much larger DeltaE00 color distance (15.19 versus 3.31). This does not rank the pairs; it shows that spectral magnitude and perceptual color distance answer different questions. Explore every measured pair and width.

Was the difference in the pixels, the panel, or the measurement?

Before treating the blue/green result as display behavior, I checked three possibilities: an image-conversion or pixel-binding mistake, a response to the exact pattern and update history, and an interaction with the meter's small contact spot. With the instruments available, I could check the software path, repeat controlled patterns, and compare contact with non-contact readings. Those tests could narrow the question, not identify every physical mechanism.

  1. Image colorAn RGB image, optionally transformed through the experimental ICC profile.
  2. Pixel selectionThe image renderer chooses six-state pixels. The investigation instead supplies exact native-state maps here.
  3. Display outputState packing, the low-level driver, the update sequence, and the reflective panel.
  4. Optical readingIllumination, viewing or contact geometry, and the instrument's spectral measurement.

The experimental patterns bypassed Pimoroni's RGB palette matching and Floyd-Steinberg dithering. Their exact 800×480 native-state maps and counts were verified before measurement. They still used the low-level driver and panel refresh path, so these comparisons did not isolate every possible software or hardware influence.

A second instrument saw selected pattern changes too

Checking the pixel maps did not answer whether the measurement itself contributed. The first instrument, an X-Rite i1Pro 3, rested on the display and supplied its own light. A Colorimetry Research CR-250 let me test selected patterns from a distance under external illumination, changing the measurement route while keeping the exact digital patterns.

Several selected patterns produced a similarly directed spectral change with the non-contact instrument. To follow changes over time and after another display update, I then recorded 108 CR-250 observations alongside i1Pro readings. The CR-250 viewed a different exposed spot on the same display presentation. Some sequences put an i1Pro reading between two CR-250 readings without refreshing the display.

Could the i1Pro 3's contact spot interact with the pattern?

The i1Pro 3 used here is the standard model. X-Rite's specification sheet lists its nominal 4.5 mm measurement aperture. At about 0.20 mm per display pixel, that diameter spans roughly 22.5 pixels. A finite spot can weight fine patterns differently with placement, phase, and local optical behavior.

Simple hard-circle models did not explain the observations by themselves. They do not measure the real optical weighting.

Already measured: CR-250 → i1Pro 3 → CR-250 sequences on an unchanged display presentation. The i1Pro was already touching the panel, and the CR-250 observed another exposed spot.

Still an open comparison: repeat that sequence alongside a matched waiting period with no i1Pro reading. That would help distinguish change associated with using the i1Pro from change that also happens while waiting. The completed interleaving does not provide that matched control. Placing or moving the contact instrument would be a separate test; none of these comparisons alone identifies a single physical mechanism.

The CR-250's radiance and the i1Pro 3's reflectance factor are different quantities. Cross-route comparisons here concern spectral direction, not pooled numerical magnitudes.

What the checks narrowed, and what stayed open

I connected exact pixel generation, automated display updates, spectral acquisition, and comparison with saved predictions into one measurement workflow. This made it practical to repeat constructions and broaden the investigation beyond blue/green stripes.

The investigation quickly became more than horizontal versus vertical

The blue/green stripes were only the clue. The investigation expanded to all 15 pairs made from the display's six native colors, with one-, two-, and three-pixel constructions measured in several sequences. It also kept the axis fixed while regrouping colors and compared a full-screen pattern with a small patterned square surrounded by white. The results vary too much for one simple orientation or width rule.

Yellow-containing pairs were prominent, but the partner changed the result. Black/yellow, yellow/red, yellow/blue and yellow/green had large color separations; white/yellow was small. Red/green was large without yellow. Across the full set, horizontal was not always lighter.

Holding an image and drawing it again gave different answers

A displayed image could remain fairly steady while held, yet return to a different color after another update or setup. The direction depended on the pattern. That made presentation history part of the prediction question, rather than a single correction to apply to every color.

Hold the imageLeave the pixels displayed and measure how the reading changes with time.
Draw it againSend another update and measure whether the same construction returns to the same color.

Tests with different preceding images and an extra white update did not reveal a consistent clearing procedure. One proposed reset sequence, blue then white before returning to the same white/blue/green pattern, changed the reading in the opposite direction to the intended correction. Those results narrowed which remedies were worth pursuing; they did not rule out every history effect.

Why waiting, redrawing, and changing the previous image are separate tests

The experiments compared changes within held episodes with changes after another refresh, and also tested returns after different preceding images. The extra-white test did not consistently improve the result, and the white control itself changed on return. A curve fitted to the recorded time trend can describe those readings, but it is not a prediction made before measuring them. Normal display use is still one update followed by a held image.

Fixed-axis organization

Exact row organization mattered even without changing orientation

These comparisons extend the same investigation beyond horizontal versus vertical. They keep the patterns horizontal and ask how the measured color changes when the row sequence, starting position, and run grouping change. Together, they show that orientation was only one way exact organization could change the measurement.

Same counts, different row order

This comparison kept both patterns horizontal and used the same 96,000 black, 192,000 yellow, and 96,000 blue pixels. One four-row period alternated yellow–blue–yellow–black; the other placed the two yellow rows together as yellow–yellow–blue–black. The display received two exact pixel arrangements, not two names for one image.

Color change with the stripe axis fixed

The cyclic pattern measured lighter and more yellow in both presentation orders. Its signed Lab change was ΔL* +15.39 / +15.51 and Δb* +11.04 / +12.04.

Perceptual color distance

DeltaE00 was 15.390 in the first order and 15.573 in the reversed order. This is an unsigned separation under nominal perfect-diffuser D50 convention. It describes color separation, not a visibility or significance verdict.

What the spectrum added

All 36 measured bands pointed in the same signed direction in both orders. Spectral RMS was 12.083 and 12.200 percentage points.

What repeating the order checked

The two signed spectral shapes had cosine 0.999900; their vector discrepancy was 0.207 percentage points RMS. Movement between repeat readings of the same pattern remains context, not an uncertainty limit.

Finding: the large measured contrast is not unique to turning horizontal stripes into vertical stripes. Overall color counts alone are insufficient to describe these two exact three-color pixel patterns. This does not prove that adjacency, grouping, or any other single construction detail caused the difference. These discovery comparisons had not yet tested whether a model could predict either absolute output; the later prediction tests address that question.

Three open questions guide the work now

Work in progress. Narrow tests have produced useful predictions, but none of the three questions below is settled. A dependable prediction model, better image reproduction from a prediction-guided renderer, and a measured profile for that renderer remain goals, not completed results.

  1. Can we predict new absolute colors across useful conditions and repeated occurrences?

    Forecast new constructions, then check whether familiar ones return to the expected color under the conditions we intend to use.

  2. Do predictions work for regions inside previously unseen images?

    Find out what a model needs to know about a region and its surroundings to predict its measured color.

  3. Can predictions help reproduce requested colors and images better?

    Use the forecast to choose better pixels while preserving shading, texture, and edges.

The forecast needs each absolute color, expressed as XYZ and Lab coordinates, not only the difference between two patterns. Predicting the full spectrum is a richer option, not a requirement for every useful color forecast.

Can we predict new absolute colors across useful conditions and repeated occurrences?

Current answer: not reliably yet. Across 14 new colors measured twice, the better average prediction did not translate into broad accuracy: each method met the chosen limit on only 2 of 28 readings. Among selected known-pattern returns, only three of six patterns stayed within the chosen error limit on every return. Early success on eight readings of two exact patterns, followed by a failed extension, made those broader checks necessary.

A separate known-pattern test shows both the success and the limitation: the same fixed predictions met the limit on 6 of 24 readings in one setup and 24 of 24 in a later setup. These were six familiar patterns, not new-color or unseen-image predictions; the result changed across occurrences without changing those forecasts. See the two setup comparisons.

What needs testing: whether a fixed model can predict both new constructions and familiar patterns when they return. Define its inputs and intended conditions, save the forecasts and success criterion, then collect fresh readings without changing the rule.

How the repeated-pattern forecasts improved

Can predictions help reproduce requested colors and images better?

Current answer: not demonstrated. A model predicts what a pattern will produce. A renderer must choose pixels that reproduce the image's requested color. An accurate forecast can still describe the wrong color.

In one two-target experiment, a candidate forecast its own output within the chosen limit on all eight readings. This did not establish an improved renderer.

What needs testing: compare a fixed baseline with a prediction-guided candidate on new colors and images. Save the candidate and its forecasts before measuring requested-color error, and check tone, detail, texture and edges as well as color.

How the renderer candidates handle color error

Two renderer candidates, two different errors

I compared two ways of distributing color error while constructing a pixel pattern. Both use measurements of the six native colors to choose pixels, then pass the remaining error to neighboring pixels.

  • B, the measured-reference baseline: bounds each color request, including error received from neighboring pixels, to the range spanned by the six references before choosing a pixel. The part outside that range is discarded.
  • C, the source-first alternative: maps the original color request into that range first, then adds and diffuses the incoming error without clipping it again.
  • D, the target-compensation trial: adjusts the requested color using ratios from earlier baseline measurements, then renders that adjusted request through C.

The reference range is a numerical boundary in XYZ, not a measured gamut of mixed pixel patterns. Both B and C select native references using Lab distance and distribute XYZ error.

B had earned its baseline role in a separate comparison with its predecessor A: it met all eight relative-improvement checks for the two tested colors, although all 32 A/B readings still missed the absolute desired-color goal. A later B/C comparison met none of its four replacement checks, so B remained the baseline. These selection tests are separate from the output-forecast experiment plotted below.

Earlier comparisons: how the prediction method developed

Closer on average was still not accurate enough for new colors

In the September 8 test, 14 new colors were each measured twice. The ratio-based forecast reduced the mean error on those 28 new-color readings to 2.69 DeltaE00, compared with 6.73 for direct averaging. Each method met the chosen limit of 1 on only 2 of 28 readings, with one color passing both repeats. Neither passed the new-color test.

Four familiar-color readings and four readings of neutral and warm squares in a synthetic dark/light surrounding image passed separately. Both methods used the same forecast for these controls because their input queries exactly matched familiar colors. These cases tested condition transfer, not which method was better or broad image accuracy. The full occurrence contained 39 readings: 36 were scored against both forecasts and three unscored white/blue/green witness readings described the display's behavior without normalizing the results.

What the surrounding-image comparison tested

The same neutral and warm color requests were placed inside a synthetic image with dark surroundings on the left and light surroundings on the right. Rendering the entire image again changed both its surroundings and the central pixel pattern. This tested whether a full-field color forecast transferred into that context; it did not isolate the cause of any difference or validate arbitrary images.

Each source was 800 × 480 pixels, with a 160 × 160 central square. There were two readings per color. This differs from the earlier exterior-substitution test, which kept the central native pixels unchanged.

What the ratio model changes

The direct method averages measured XYZ from nearby input colors. The ratio method instead averages how those measurements differ proportionally from a native-color estimate, then applies that ratio to the new input's estimate. That estimate uses the actual emitted pixel counts and a fixed historical set of six native-color measurements.

In development, each evaluated pattern and all of its repeats were left out of its prediction's training data. The ratio method reduced average error, but this was a comparison within the collected batch, not a fresh validation result. The September 8 test reported here used predictions saved before acquisition.

What changed when the model chose neighbors by native-color proportions

The alternative chose neighboring examples by their emitted native-color proportions rather than similarity in requested color. Replaying the September 8 test worsened the mean error from 2.688 to 2.799 DeltaE00. In a separate development comparison that left each target out of its own training data, the mean improved from 2.152 to 1.761, giving each of the 33 patterns equal weight. Only 13 of 55 individual reading errors were at or below 1.

This neighbor rule was chosen after reviewing the September 8 results. Both comparisons are retrospective development on existing observations, not prospective validation or new measurements. The later library-expansion test above kept this native-proportion neighbor rule the same in both versions.

A future renderer could use predictions only within conditions where they survive fresh tests. No dependable range of use has yet been established. The path from a forecast to a measured ICC profile therefore has several distinct checks:

  1. 1 · Predict outputsTest new constructions and returns within defined conditions.
  2. 2 · Check unseen imagesTest region forecasts in pictures not used to choose the model.
  3. 3 · Compare renderersCheck whether prediction-guided choices improve requested color without losing image detail.
  4. 4 · Freeze the processSelect the renderer and display condition only after the intended use is supported by fresh measurements.
  5. 5 · Characterize with ICCIf that fixed process is supported, a future measured profile could describe its color response.

The new ICC builder's current profiles are model-only software checks, not device characterization. If a renderer and condition are frozen and supported by fresh measurements, a measured profile could characterize the color response of that fixed process. It would not execute the renderer or store the display's update history. The ICC's profile specifications define the interchange format.

The practical goal is better color without losing the picture. Reliable pattern forecasts and tests inside new images both support that goal. A later model-guided rendering choice will need to improve the requested color while preserving shading and detail, and work through different image surroundings and repeated display updates. Each comparison needs a defined viewing condition, color reference, and success criterion fixed before fresh validation measurements.

Characterizing this display has been slower and more challenging than I expected. Each new pattern needs a display update, time to settle, and repeated measurements; a plausible color model can still miss what the panel produces. That has also made it a rewarding way to connect color science, electronics, software, and experimental design. The goal remains practical: understand the output well enough to make better choices when rendering an image.

A deeper mathematical explanation will accompany a tested model and a clearly defined range of use.
